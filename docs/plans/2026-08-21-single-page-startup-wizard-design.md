# 单页启动配置向导设计

## 目标

将首次进入系统的 P1 启动清单改为同一工作台内完成的三步真实配置流程。用户不再在“清单”和三个独立工作区之间跳转；每次只处理当前一个完整业务闭环，成功后自动进入下一步。

## 体验与边界

- 工作台正文顶部是横向三步进度轨道：建立实训周期、配置运营模板、组织实训人员。
- 轨道下方是唯一的“当前配置”区域，只渲染当前步骤的真实表单或完成结果，不呈现一组小卡片。
- 通知仍保留首次欢迎与当前任务，但按钮只将用户带到同页当前配置区域，不再打开另一页面。
- 进度由治理服务的实际数据计算，前端不保存“已完成”的影子状态：
  - 存在实训周期及门店，第一步完成；
  - 存在已发布模板，第二步完成；
  - 当前周期存在启用团队，且至少一名启用成员归属该团队，第三步完成。
- 待审批账号属于第三步的可选工作；它不能替代创建团队并加入已启用成员这个完成条件。
- 不改动后端接口，不读取、迁移或兼容任何旧系统数据。

## 页面结构

```text
应用栏：当前角色 + 通知
主内容
  启动清单标题与简短说明
  横向进度轨道（3 个编号、连接线、完成/当前/受阻状态）
  当前配置区域
    当前步骤的真实表单（周期 / 模板 / 人员）
  轻量状态说明或重试提示
```

进度轨道是语义化有序列表；当前项以 `aria-current="step"` 标识。它用于告知状态而不是伪装成三个导航卡片。完成项与受阻项不提供无效按钮。窄屏仍保留横向的三等分布局，允许说明文字换行，避免把流程退化为卡片堆叠。

## 组件与数据流

`DashboardPage` 负责读取周期、门店、模板、团队和成员关系，计算三步状态及当前步骤。它在配置区域以嵌入模式复用既有的：

- `TermWorkspacePage`：调用原子 `POST /api/v1/admin/initialization`；
- `TemplateWorkspacePage`：创建草稿并调用真实发布接口；
- `PeopleWorkspacePage`：审批申请（可选）、创建团队、加入学期成员。

三个页面增加 `embedded` 外观模式：移除“返回工作台”和重复的治理页眉，保留现有表单、校验、错误处理与真实 API 调用。成功回调触发 Dashboard 重新从服务端读取进度并切换到下一步；刷新或并发变更后也能回到服务端实际决定的当前步骤。

`App` 不再维护工作台/周期/模板/人员四个内部路由状态，认证后的 P1 直接进入单页工作台。

## Material 3 落地规则

- 使用主内容与辅助状态的清晰层级、紧凑的横向流程和响应式栅格，而非密集卡片。布局遵循 [Material 3 canonical layouts](https://m3.material.io/foundations/layout/canonical-examples/overview) 的主次内容与自适应原则。
- 当前、完成、受阻三个状态只使用一致的颜色、轮廓、文字和状态层，不依赖颜色本身传达含义；交互控件保留 MUI Material 3 风格的焦点、悬停、按下与禁用状态，符合 [Material 3 interaction states](https://m3.material.io/foundations/interaction/states/overview)。
- 表单保持已建立的标签、帮助文本、错误提示和主要按钮语义。成功是推进事件，失败留在当前表单并保留错误上下文。

## 验收

1. 新 P1 打开工作台时，页面展示横向三步轨道及第一步“建立实训周期”的真实表单；没有独立页面跳转。
2. 提交原子初始化成功后，服务端状态刷新，轨道第一步完成，当前配置自动变为模板表单。
3. 草稿创建后仍停留第二步，只有模板发布成功才推进到人员组织。
4. 创建团队并将已启用账号加入该团队后，第三步完成；待审批账号为空不阻塞完成。
5. 通知中的当前任务不会改变路由，而是定位到同页的当前配置。
6. 原工作区单独渲染时仍保留返回工作台的上下文，已有治理页测试继续通过。
