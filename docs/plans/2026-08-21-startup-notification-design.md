# 启动清单通知入口设计

## 目标

将 P1 首次进入系统时的引导信息从首页正文移至可操作的通知入口，避免正文重复展示欢迎语，同时保留进入启动清单的明确路径。

## 交互

- 顶部栏保持单行：左侧只显示当前角色，右侧显示带未完成数量的通知图标。
- 点击图标打开锚定式通知面板；面板含“运营工作台”、欢迎语、当前启动状态说明和“前往建立实训周期”动作。
- 动作使用 Dashboard 已计算出的当前可执行步骤，首次进入时直接打开周期工作区。
- 当启动清单完成时，通知面板显示“启动清单已完成”，不显示无效引导动作。
- 首页正文移除同一组“运营工作台 / 欢迎回来 / 当前尚未建立实训周期”文字，只保留启动清单与服务端状态区域。

## 边界

- 不依赖 MUI 运行时生成的 `css-*` 类名；使用组件和语义标签定位行为。
- 通知入口不是静态装饰：只呈现当前服务端确认的启动状态并调用既有工作区导航。
- 不新增后端接口、不读取旧数据、不在浏览器保存任何治理状态。

## 测试

- Dashboard 测试验证首次进入时通知按钮可见、点击后显示引导并能打开周期工作区。
- 完成全部启动项的测试验证通知面板没有过期的“建立周期”行动。
