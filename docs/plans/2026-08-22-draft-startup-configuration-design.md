# 草稿式启动配置设计

## 目标

让 P1 在同一启动工作区内完成实训周期、运营模板和实训人员配置。首次按顺序建立草稿；已完成的前序步骤可回退查看和编辑；只有最后一步由 P1 明确发布后，周期与模板才会进入生效状态。

## 交互模型

启动工作区保持上下两层：上方为扁平三步进度轨道，下方为当前选择步骤的配置主体。

- 首次进入时自动停在第一个尚未完成的步骤。
- 已完成步骤可在进度轨道上点击回看；未满足前置条件的后续步骤不可点击。
- 当前主体区的工具栏左侧放置“返回上一步”，仅当上一步已可查看时显示；右侧放置当前步骤唯一主操作。
- 主操作复用主体内同一个真实表单提交，不在表单底部重复放置按钮。
- 第一步首次操作为“创建实训周期”；已有草稿后为“保存修改”。
- 第二步首次操作为“保存模板草稿”；已有草稿后为“保存修改”。不得在第二步发布。
- 第三步用于维护团队与学期成员。满足最低人员组织条件后，工具栏右侧显示“发布实训配置”。
- 发布成功后周期和当前草稿模板均成为 `PUBLISHED`，启动清单显示完成；发布后的对象不允许原地修改。

## 草稿与发布规则

| 对象 | 草稿期间 | 发布后 |
| --- | --- | --- |
| 实训周期 | 可改名称、开始/结束日期 | 只读；后续变更必须进入新的配置流程 |
| 运营门店 | 可改名称与启用状态；代码不可改 | 继续由全局门店治理接口管理 |
| 首个教学周 | 可改名称、日期、阶段；必须位于周期日期内 | 只读 |
| 运营模板 | 可改名称、生效日期、配置、首个岗位和首项 SOP | 不可原地修改 |
| 团队与成员 | 可创建团队、加入成员、停用成员 | 保留既有治理规则与审计 |

代码是稳定业务标识，创建后不允许修改。每次保存均携带对象版本号；版本冲突由服务端返回 `409`，前端使用 Toast 告知用户重新加载。

## 后端契约

### 原子保存第一步

`PATCH /api/v1/admin/startup-configurations/{termId}` 同一事务更新草稿周期、关联门店及第一教学周。请求中携带三者的 `version`；任一校验或乐观锁失败时全部回滚。

```json
{
  "term": { "name": "2026 秋季实训", "startDate": "2026-09-01", "endDate": "2027-01-20", "version": 1 },
  "store": { "id": "uuid", "name": "饮品实训门店", "status": "ACTIVE", "version": 1 },
  "firstTeachingWeek": { "id": "uuid", "name": "导入与准备", "startDate": "2026-09-01", "endDate": "2026-09-07", "phaseCode": "PREPARATION", "version": 1 }
}
```

### 原子保存第二步

`PATCH /api/v1/admin/template-versions/{templateVersionId}/starter-configuration` 同一事务更新草稿模板、首个岗位和首项 SOP。模板版本及两个组件分别带版本号；模板必须保持 `DRAFT`。

### 最终发布

`POST /api/v1/admin/startup-configurations/{termId}/publish` 同一事务发布指定草稿周期和指定草稿模板。请求带两者版本号；服务端必须确认：

1. 模板属于该周期；
2. 周期和模板均为草稿；
3. 本期至少存在一个活跃团队，且至少有一个活跃成员归属于活跃团队；
4. 版本匹配。

成功返回已发布的周期与模板。审计记录分别记载两类对象的发布操作。

## 前端数据与错误处理

`GovernanceApi` 承载所有读取、保存与发布请求，页面不得直接使用 `fetch`。Dashboard 在每次保存、成员变更和发布成功后重新读取服务端状态；因此进度始终由真实数据驱动。

阻断性的初始加载问题仍使用 `PageState`，提交失败、校验拒绝和版本冲突都放入全局 Toast。字段级必填校验保留在字段下方。

## 验收

1. 周期创建后能回退到第一步，修改周期、门店和首周并通过一次原子保存生效。
2. 模板在第二步只保存草稿，可反复编辑；不出现提前发布按钮。
3. 已完成进度项可查看，未满足前置条件项不可进入。
4. 第三步满足人员组织条件后，唯一主操作是发布；发布后周期和模板均由服务端返回 `PUBLISHED`。
5. 表单底部没有重复操作行，当前步骤工具栏左侧为回退，右侧为当前主操作。
6. 任意对象版本冲突或业务拒绝不显示假成功，且不遗留部分更新。
