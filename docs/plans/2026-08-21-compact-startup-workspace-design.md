# 紧凑启动工作台设计

## 目标

将首次配置页面收敛为适合 1920×1080 桌面显示器的一屏工作区。页面不展示重复的引导标题或长说明，主区域居中，并明确分为上下两部分：进度与当前配置。

## 布局

```text
应用栏（固定既有高度）
主区域：全高、水平和垂直居中
  上部：扁平三步进度轨道
  分隔线
  下部：当前步骤的主体表单
```

- 删除截图中的“启动清单”标题及其说明。
- 删除“当前配置”标签、重复的“建立实训周期”标题及其长说明；表单只保留必要的分组名称与字段标签。
- 上部不作为卡片或导航，始终横向展示三步、完成/当前/等待状态及连接线；当前项用 `aria-current="step"` 表示。
- 下部根据服务端计算出的当前步骤切换周期、模板或人员表单。步骤提交成功后仍由服务端状态决定下一项。
- 在宽度至少 1280px 的桌面环境，周期表单采用三列紧凑栅格：周期两项、门店两项、首周三项和提交按钮都在可见主区域内；窄屏仍可自然改为单列滚动。
- 主区域以可用视口高度为基准居中，控制桌面端间距而非使用固定页面高度，避免遮挡或裁切浏览器缩放后的内容。

## 日期交互

使用 MUI X `DatePicker`（Material Design 风格），搭配 `LocalizationProvider`、`AdapterDayjs` 和中文 locale。日期字段保留键盘输入、错误信息与标签，同时提供桌面端 Popover 日历和移动端对话框日历；提交给 API 时统一序列化为 `YYYY-MM-DD`。

选型依据：MUI 官方说明 `DatePicker` 在桌面使用 Popover、移动端使用 Modal，并提供 field 与 calendar 的组合交互；MUI X 8 的 peer dependency 明确支持现有的 Material UI 7。见 [MUI X Date Picker 文档](https://mui.com/x/react-date-pickers/date-picker/)。

## 验收

1. 首次进入时页面没有上述两块重复引导文案。
2. 1920×1080 桌面下，应用栏以下的“进度轨道 + 周期表单”居中且无需主页面滚动。
3. 进度轨道一直位于主体表单上方，且当前步骤由真实服务端数据决定。
4. 每个日期字段可打开 Material 日历，选择后仍以 `YYYY-MM-DD` 调用现有原子初始化接口。
5. 模板与人员步骤继承同样的上下层结构及紧凑桌面间距。
