# 克制型 Material 3 Expressive 前端全量重构设计

**状态：** 已确认，待实施

**日期：** 2026-08-22

**适用分支：** `renovate`

**参考：** [Material 3 Get started](https://m3.material.io/get-started)、[Canonical layouts](https://m3.material.io/foundations/layout/canonical-examples/overview)、[Interaction states](https://m3.material.io/foundations/interaction/states/overview)

## 1. 目标与范围

本设计将现有 React 前端整体重构为克制的 Material 3 Expressive 工作台。重构覆盖登录、首次修改密码、应用壳层、启动配置、实训周期、运营模板、人员组织、日期选择、状态页、Toast 和状态标签，并为后续业务页面建立唯一视觉与交互基线。

重构只改变前端信息架构、视觉层级、响应式布局和交互反馈，不改变真实 Spring 后端接口、角色权限、草稿发布规则或业务状态机。不得引入旧数据兼容、模拟成功数据或第二套组件体系。

## 2. 设计原则

### 2.1 工作任务优先

- 每个页面只突出一个当前主任务；辅助信息退入 supporting pane、说明文字或弹出层。
- 不使用大量小卡片平均分割信息。表单、列表和状态使用连续表面、留白、分组标题与轻分隔建立层级。
- 页面标题、当前上下文、主要操作和主体内容保持稳定顺序，不让按钮漂浮在无语义空白区。

### 2.2 克制的 M3 Expressive

- 保留 Material 3 的色彩角色、状态层、形状、排版和自适应骨架。
- Expressive 只用于当前导航、关键动作、页面转场和少量品牌形状；不使用装饰性大卡片、夸张阴影或持续动画。
- 清爽专业的现代饮品品牌由奶白表面、深茶绿、薄荷色 tonal container 和温和的圆角体现。

### 2.3 可达与可信

- 交互状态至少通过颜色之外的一种信号表达，例如图标、文字、形状或描边。
- 所有图标按钮具备可访问名称和 Tooltip；键盘焦点始终可见。
- 服务端是状态事实来源。前端不得通过视觉乐观状态掩盖提交失败或版本冲突。

## 3. 全局视觉系统

### 3.1 色彩角色

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| Primary | `#176B5B` | 主操作、当前步骤、焦点和品牌识别 |
| On primary | `#FFFFFF` | Primary 容器上的内容 |
| Primary container | `#BCEEDB` | 当前导航、tonal 按钮、选中状态 |
| Surface | `#FBFBF7` | 应用背景 |
| Surface container | `#F3F5F0` | 导航、表单工作区、列表分组 |
| Surface container high | `#E9ECE7` | hover、辅助面板和更高层级表面 |
| Outline | `#707A73` | 控件描边、次级分隔 |
| Error | `#A63C3C` | 字段错误、阻断性失败 |
| Warning | `#9A5900` | 待处理、风险与警告 |

禁止在业务组件中继续增加 `rgba(...)`、任意十六进制颜色或独立阴影。需要透明度时从主题状态层 Token 生成。

### 3.2 排版

- 中文使用 `PingFang SC`、`Microsoft YaHei` 和系统无衬线回退；英文与数字使用 Inter/system-ui 回退。
- 页面标题使用 28px/36px、700；区块标题使用 18px/26px、700；正文使用 14–16px。
- 不再使用全大写品牌副标题。编号、日期和状态保持等宽数字特性。
- 标题层级必须连续：页面 `h1`、区块 `h2`、子区块 `h3`。

### 3.3 形状、间距与层级

- 圆角分为 12px、16px、24px 和 full；输入框默认 16px，主表面 24px，图标操作使用 full。
- 间距使用 4px 基线，常用间距为 8、12、16、24、32、40。
- 页面主体不用投影。只有 Popover、Toast、菜单和关键浮层使用 elevation。
- 分隔优先使用表面色差和留白；只有结构边界不清时才使用 1px outline variant。

### 3.4 动效与状态层

- hover、focus、pressed 和选中状态统一由主题状态层实现。
- 常规过渡 160–240ms；步骤切换只做轻微淡入和位移，不做缩放弹跳。
- `prefers-reduced-motion` 下移除非必要位移和过渡。

## 4. 自适应应用骨架

### 4.1 断点

| 模式 | 宽度 | 布局 |
| --- | --- | --- |
| Compact | `< 840px` | 单栏、顶部栏、抽屉或底部操作 |
| Medium | `840–1199px` | 主内容为主，辅助区按需折叠 |
| Expanded | `>= 1200px` | 导航轨道或 supporting pane，正文最大宽度 1200px |

### 4.2 顶栏与导航

- 顶栏保持单行 64px，只显示角色、通知和账户入口。
- 桌面业务导航使用 80px rail；需要文字时扩展到 240px。当前仅有启动治理时不伪造空导航。
- 通知保留右上角入口，内容在 M3 Popover 中展示；通知不重复出现在页面正文。
- 页面主区域使用统一 `PageScaffold`，负责最大宽度、页面标题、描述、上下文、操作和响应式 gutter。

## 5. 页面设计

### 5.1 登录与首次改密

- Expanded 模式采用 5:4 双栏：左侧为低对比品牌语境和产品说明，右侧为不带厚边框的认证表单。
- Compact 模式隐藏装饰性品牌面板，表单单栏居中。
- 登录表单只保留产品名称、用途说明、账号、密码和主操作；删除 `BEVERAGE OPS`。
- 密码页复用认证骨架，密码规则使用安静的 supporting text，不与错误信息竞争。

### 5.2 启动配置工作台

- 页面上下两部分保持不变：顶部为步骤导航，下面为当前步骤工作区。
- 步骤导航高度控制在 72–80px。当前步骤使用小型 primary-container 选中态；完成步骤使用对勾；阻塞步骤使用轮廓与辅助文字。
- Expanded 模式下，步骤主体使用 supporting-pane：主表单约占 2/3，右侧操作区约占 1/3。
- “创建实训周期”使用带 Tooltip 的半透明前进图标按钮，固定在右侧操作区的纵向中心，不再悬浮在无语义空白中。
- Medium/Compact 模式下辅助操作区并入主体底部并保持右对齐；不得覆盖输入框。
- 1920×1080 浏览器可视区域内，每个启动步骤不得产生页面级纵向滚动；人员长列表允许在限定区域内滚动。

### 5.3 周期与模板

- 统一使用 `WorkspaceSection`：区块标题、可选说明、两列字段区。
- 输入框采用 56px filled/tonal 风格，字段横向间距 16px，区块纵向间距 24px。
- 周期页保持“周期与时间、运营门店、首个教学周”三组；模板页保持“模板版本、首个岗位、首项 SOP”三组。
- 只在独立页面显示说明文案；嵌入启动工作台时只保留区块标题。
- 草稿保存和最终发布语义保持原规则，不以视觉重构改变业务流程。

### 5.4 人员组织

- 周期选择放入页面上下文栏。
- “待审批账号、已启用账号、团队与本期成员”使用连续的扁平列表或表格区块，不创建账号卡片矩阵。
- 待审批操作在同一行完成角色、说明和批准；窄屏转为纵向表单。
- 一次性凭据使用明确的高优先级信息面板，关闭或离开后不再显示。
- 团队创建与成员加入分别成为清晰的内联工具栏，成员列表使用稳定列对齐。

### 5.5 公共状态

- `PageState` 统一处理加载、空数据、错误、离线和无权限，保持标题、说明和操作顺序一致。
- Toast 是业务错误、警告和操作结果的唯一文字提示出口。
- 字段校验失败时，字段显示 `aria-invalid`、错误轮廓和图标；Toast 汇总需修正的字段并将焦点移动到第一个无效字段，不在所有字段下重复铺开红色句子。
- `StatusChip` 使用 tonal 色彩和图标/文字组合，不只依赖颜色。

## 6. 组件边界

重构后公共 UI 至少包括：

- `PageScaffold`：页面宽度、标题、描述、操作和响应式 gutter。
- `AuthScaffold`：登录与改密的双栏/单栏骨架。
- `StartupStepper`：启动步骤、完成和阻塞状态。
- `SupportingActionPane`：当前步骤说明和唯一主操作。
- `WorkspaceSection`：表单与详情的扁平分组。
- `FormErrorSummary`：Toast 摘要和首个错误焦点协调。
- `PageState`、`StatusChip`、`MaterialDateField`：统一到新 Token。

页面只能组合这些语义组件和 MUI 基础控件，不得再次复制 `FormSection`、页面标题栏或硬编码状态色。

## 7. 数据与交互边界

- 保持 `AuthProvider`、`GovernanceApi`、真实 HTTP 请求和服务端状态读取方式不变。
- 视觉重构不得新增后端端点、旧数据适配或本地持久化业务状态。
- 提交成功后仍按现有方式刷新服务器状态并推进步骤。
- 加载失败使用阻断状态页；提交失败、权限拒绝、版本冲突和校验汇总使用 Toast。
- 所有图标提交控件仍具备 `type="submit"`、`form`、无障碍名称和 Tooltip。

## 8. 验收标准

1. 登录、改密、启动配置、周期、模板和人员页面使用同一套色彩、排版、形状、间距和状态层。
2. 页面不存在 `BEVERAGE OPS`、重复介绍文案、漂浮无归属按钮或小卡片矩阵。
3. 启动配置在 1920×1080 下不产生页面纵向滚动，主体居中且不超过 1200px。
4. 390×844、1024×768、1440×900 和 1920×1080 下均无横向溢出；关键操作不覆盖内容。
5. 初次进入表单不显示错误；提交无效表单时 Toast 提供汇总，焦点进入第一个错误字段。
6. 所有现有 Vitest 业务测试继续通过，并新增主题、响应式骨架、表单错误和启动步骤结构测试。
7. ESLint、TypeScript 和 Vite 生产构建通过；Docker Web 容器使用新构建运行。
8. 登录、周期创建、模板草稿、人员组织、回退编辑和最终发布继续调用真实后端接口。

## 9. 明确不做

- 不改变后端接口、数据库结构、权限或发布规则。
- 不实现尚未进入当前前端的 PRD 业务页面。
- 不引入 Material Web Components 与 MUI 并行的第二套组件库。
- 不增加暗色主题、装饰性插画下载、复杂品牌动画或可自由配置的主题编辑器。
- 不兼容任何旧前端、SQLite 或 PocketBase 数据与页面。
