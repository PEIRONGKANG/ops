# 全局 Toast 提示设计

## 目标

将非阻断性的错误、警告、成功和信息反馈从页面内容中移出，统一经由全局 Toast 展示，保持启动配置工作区的稳定布局。

## 交互边界

- `error`、`warning`、`success` 与 `info` 使用同一个右下角 Toast 队列；同一时间只显示一条，按触发顺序依次展示。
- Toast 通过 MUI `Snackbar` 承载；内容使用对应的 Material 状态色与清晰的关闭按钮。普通提示自动关闭，错误和警告保留更长时间。
- 需要立即恢复操作的短暂错误可以在 Toast 内提供一个实际可用的操作，例如“重试”。
- React Hook Form 的字段级校验（输入框下的必填、格式说明）保留原位，因为它是输入纠正提示，而不是操作结果。
- 数据无法加载、没有权限或离线等阻断性状态继续使用 `PageState` 与其重试按钮；此时页面主体本身不可用，不能仅以自动消失的 Toast 代替。
- 一次性临时密码不是警告提示，改为明确的凭据交付内容区，不进入自动消失的 Toast，避免敏感凭据被短暂提示隐藏或误传达。

## 架构

```text
AppThemeProvider
  ToastProvider
    AuthProvider
      页面 / 领域工作区
        useToast().show({ message, severity, action? })
```

- `ToastProvider` 维护队列、当前消息和关闭策略；页面不直接渲染 `Snackbar` 或结果型 `Alert`。
- `useToast` 是唯一的触发入口。业务组件在 catch 分支发出错误/警告，在完成操作后发出成功提示。
- 组件继续保留业务状态（例如已创建的周期、模板版本和人员列表）；Toast 只负责反馈，不承担数据状态。

## 覆盖范围

- 认证：登录、初次密码修改。
- 启动工作台：状态同步失败与重试。
- 治理：周期初始化、模板创建/发布、人员审批、创建团队、加入学期成员。
- 清除这些页面内用于操作结果的 `Alert`；不改变后端接口、业务规则或字段校验。

## 验收

1. 操作失败或完成时，页面内容高度不因结果提示发生变化。
2. Toast 能正确呈现错误、警告和成功状态；重试动作能实际再次调用对应加载逻辑。
3. 字段校验和阻断性 `PageState` 保持可用。
4. 已批准账号的一次性凭据仍明确可见，且不会放入自动关闭的 Toast。
