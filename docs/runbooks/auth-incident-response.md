# 身份认证安全事件处置手册

适用范围是新 PostgreSQL 身份域中的本地帐号和刷新会话。旧 SQLite/PocketBase/FastAPI 数据不在本系统的恢复或兼容范围内。

## 刷新令牌疑似泄露或重放

系统检测到已旋转或已撤销的刷新令牌时，会返回 `401 REFRESH_REUSED` 并撤销整个同源会话家族。P1 应：

1. 确认目标帐号与 `iam_auth_events` 的时间线；审计中只应有 HMAC IP、请求 ID 与安全元数据。
2. 通过 P1 重置密码接口重置该帐号，确保撤销该帐号所有会话并强制改密。
3. 通过受控渠道交付一次性临时密码。
4. 若怀疑 JWT 或 HMAC 密钥泄露，立即在密钥管理系统轮换密钥、滚动重启服务，并对受影响帐号重置密码。

不要试图恢复已撤销的会话，不要用 SQL 修改 `iam_refresh_sessions`，也不要把 Cookie、JWT 或原始 IP 导出到事件工单。

## 帐号误用、离岗或权限变化

- 离岗或可疑帐号：P1 调用禁用接口。它会递增授权版本并撤销全部会话。
- 忘记密码：P1 调用重置接口。临时密码仅在响应中出现一次。
- 恢复人员：P1 调用重新启用接口，系统强制使用新的临时密码改密。
- 角色改变：必须通过受审计的 P1 治理流程完成；授权版本变化后，旧 access token 在下一次受保护请求即失效。

## 审计和取证边界

只查询 `iam_auth_events` 的事件类型、帐号关联、请求 ID、HMAC IP 与安全元数据。严禁向审计表写入或从其中寻找密码、临时密码、JWT、刷新 Cookie、领取密钥或原始 IP；它们按设计不会被保存。

## 禁止的恢复方式

- 不迁移旧 SQLite/PocketBase/FastAPI 用户、密码哈希、角色或会话。
- 不执行“兼容登录”“双写”“回填”或直接 SQL 密码修改。
- 不复制生产数据库覆盖新环境；每个环境由 Flyway 从空 PostgreSQL 数据库创建。

若需要历史档案，只能以只读参考资料方式访问，不能成为新身份认证的事实来源。
